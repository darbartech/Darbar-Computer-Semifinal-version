# Sensitive-file cleanup

What belongs out of the repository, what was actually found, and the commands to run if a
copy of this project ever carries private data into git.

Money, certificates and uploads make this repository carry personal data by default:
issued certificate PDFs, uploaded photos, and Playwright traces that record the request bodies
of a signed-in admin session. None of it belongs in git.

## Done in this pass

- `.gitignore` gained `*.log`, `/src/generated/` and `/*.zip`; everything else on the list was
  already covered.
- `test-results/` (214 files, ~30 MB of traces from earlier runs) was deleted from disk. It is
  regenerated by `npm run test:e2e`, and its contents — request bodies, cookies, typed
  passwords — are exactly what must not sit around.
- `storage/certificates/` (~39 MB) and `public/uploads/` (~19 MB) were **kept**: they are the
  files the dev site serves, and deleting them breaks local media. They are ignored and
  untracked; the wipe guidance for a retired machine is at the bottom of this file.
- Nothing sensitive was ever committed here, so no history rewrite is needed — the evidence is
  below. The commands are kept for the day a clone or a fork does carry those paths.
- `prisma/seed-test.ts` now runs behind `prisma/seed-guard.ts`.

## What is now ignored

`.gitignore` covers `.env*` (with `.env.example` kept), `node_modules`, `.next`, `/storage/`,
`/public/uploads/`, `/test-results/`, `/playwright-report/`, `/src/generated/` and `*.log`.

| Path | Contains | Tracked today | In any commit |
|------|----------|---------------|---------------|
| `storage/certificates/**` | issued PDFs with a student's name, course, date and signature | no | no |
| `public/uploads/**` | student and media images | no | no |
| `test-results/**`, `playwright-report/**` | traces, screenshots, `.webm` — request bodies and cookies of a live session | no | no |
| `.env` | every production secret | no | no (only `.env.example` is committed) |
| `src/generated/prisma/**` | Prisma client, rebuilt by `npm run db:generate` | **yes — 43 files** | yes |

Verified with:

```bash
git ls-files | grep -E "^(storage/|public/uploads/|test-results/|playwright-report/|\.env)"   # empty
git log --all --pretty=format: --name-only -- storage public/uploads test-results playwright-report | sort -u   # empty
```

### `src/generated` is tracked

The ignore rule alone does not untrack it. When convenient (it is a content-free change, so
keep it in its own commit):

```bash
git rm -r --cached src/generated
git commit -m "chore: stop tracking the generated Prisma client"
```

Every clone regenerates it from `prisma/schema.prisma` on `npm ci` (postinstall runs
`prisma generate`), so nothing breaks.

### One artifact that is NOT in git but is still PII

`Darbar-Computer-Semifinal-version.zip` at the repository root (~90 MB, a whole-project
snapshot) contains certificate PDFs naming real students, files from `public/uploads/`, and
233 trace/report entries under `test-results/`. It is untracked and `.gitignore` now keeps
`/*.zip` out of the index, but the file itself still holds the data.

Move it off the working tree, or delete it once the backup it stands in for is confirmed
elsewhere:

```bash
# look first, then decide
unzip -l Darbar-Computer-Semifinal-version.zip | grep -E "storage/certificates|public/uploads|test-results" | head
```

Do not mail it, do not attach it to an issue, do not upload it to a shared drive.

## Purging a path from history (only if a clone or the remote really has it)

Re-check first; if both commands above come back empty, **skip this whole section** — there is
nothing to purge, and rewriting history would only destroy the commit graph.

When a path really is in the history, rewriting is a shared-state operation: announce it, work
on a fresh clone, and make sure nobody has unpushed commits.

### Option A — `git filter-repo` (recommended)

```bash
pip install git-filter-repo            # or: winget install / choco install git-filter-repo
git clone --mirror <remote-url> darbar-purge
cd darbar-purge
git filter-repo --invert-paths \
  --path storage/certificates \
  --path public/uploads \
  --path test-results \
  --path playwright-report \
  --path .env \
  --force
git push --force --mirror origin
```

### Option B — BFG Repo-Cleaner

```bash
java -jar bfg.jar --delete-files "*.pdf" --delete-files "*.webm" --delete-files ".env" \
  --no-blob-protection darbar-purge.git
cd darbar-purge.git && git reflog expire --expire=now --all && git gc --prune=now --aggressive
```

BFG skips the latest commit by default; `--no-blob-protection` includes it, which is what a
secret sitting in `HEAD` needs.

After either:

```bash
git log --all --pretty=format: --name-only -- storage public/uploads test-results .env | sort -u   # must be empty
```

Then ask everyone to re-clone (or `git fetch && git reset --hard origin/main`) and expire the
old blobs server-side by contacting the host's support if the objects must really disappear —
a rewritten branch does not delete a cached fork, a pull request ref, or a Git hosting
service's blob cache.

## Rotate afterwards, in this order

Rewriting history removes the copies, not the exposure. Anything that appeared in a trace,
a diff or an attachment is treated as disclosed:

1. **Database password** — `.env` `DATABASE_URL` (and the Postgres role itself if the host is
   shared).
2. **`AUTH_SECRET`** — session signing and the encryption of `TwoFactor` secrets. **Changing
   it invalidates every enrolled authenticator** (docs/08 §Two-factor for staff), so rotate it
   deliberately, with the affected staff told to re-enrol, and never as a drive-by fix.
3. **`CRON_SECRET`** — each cron entry point.
4. **Mail provider key** (`RESEND_API_KEY` or equivalent) and `MAIL_FROM`.
5. **Media provider keys** (Cloudinary cloud name, API key and secret) if uploads were ever
   signed through them.
6. **`IP_HASH_PEPPER`** if it exists — it salts every stored client address.
7. **e2e fixture passwords.** The defaults in `prisma/seed-test.ts` and `e2e/helpers.ts`
   (`E2eSuperAdmin!2026`, `E2eAdmin!2026`, `E2eEditor!2026`, `E2eCounselor!2026`) are written
   in this repository on purpose, so they are not secrets — but they *become* secrets the
   moment the fixture accounts exist on a database anyone else can reach. If `seed-test` ever
   ran against anything other than a throwaway local database, delete those accounts
   (`e2e-%@darbar.test`) or override every `E2E_*_PASSWORD` and re-seed.
8. **Any human password typed during a traced run.** A Playwright trace records the request
   body, so a real staff password entered while tracing was on is inside `test-results/`.

## Keeping the fixtures out of a real database

`prisma/seed-test.ts` now refuses to run unless **both** conditions hold:

- `NODE_ENV` is not `production`, and
- the opt-in is present: `ALLOW_E2E_SEED=1`, or the equivalent `--allow-e2e-seed` argument
  (`npm run db:seed:test` passes the argument, because an npm script cannot set an environment
  variable in a way that works in both cmd.exe and a POSIX shell).

The check itself is `e2eSeedProblem()` in `prisma/seed-guard.ts`, covered by
`tests/e2e-seed-guard.test.ts`. Anything that does not spell out the opt-in — `prisma db seed`,
a bare `npx tsx prisma/seed-test.ts`, a forgotten CI step — stops at the guard instead of
writing plausible-looking staff rows next to the real ledger.

## Student data still in the working tree

Certificate PDFs under `storage/certificates/` and images under `public/uploads/` are local
copies of records the portal serves. They are ignored, but ignoring is not deleting: before
this machine is retired, donated or reimaged, wipe the storage directory or let the retention
job (docs/09) clear it.
